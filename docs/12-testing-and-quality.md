# 12 — Testing and quality

**Audience:** implementing agents. Normative.

## 1. Test pyramid

| Layer | Tooling | What |
|---|---|---|
| Unit | `cargo test`, `proptest` | kernel operations, units parsing, query parser, tolerance helpers, migrations |
| Golden | fixtures under `crates/planyrith-core/tests/fixtures/` | native format per version, importer outputs, inference results (JSON), CLI outputs |
| CLI integration | `assert_cmd`, `predicates` | every command via `planyrith tool`, batches, exit codes, JSON schema conformance |
| RPC integration | in-process server + client | every RPC method; GUI-attach scenario |
| Render snapshots | headless `wgpu` (software adapter in CI) | per style/feature, per-pixel tolerance (`docs/06 §11`) |
| GUI | `egui` test harness (kittest) + scripted input | tool state machines, panels, shortcuts; smoke on each platform |
| Web | `wasm-bindgen-test` in headless Chrome | storage, open/save, basic modeling |
| Fuzz | `cargo-fuzz` | native reader, every importer, mesh op sequences, query parser, units parser |
| Bench | `criterion` | add_edge, face finding, push-pull, boolean, extraction, inference, open/save |

## 2. Invariant checks

- `HalfEdgeMesh::validate()` runs after every kernel operation in debug builds and in all tests;
  release builds run it in `planyrith validate` and after import.
- Undo/redo determinism: for every command test, apply → undo → compare to original bytes
  (`.plyr` deterministic save) → redo → compare to post-apply bytes.
- Cross-frontend equivalence: GUI tool tests feed the same `Params` the state machine produced
  into the CLI and assert identical documents.

## 3. Fixtures policy

- Small (< 1 MB), generated by scripts in `tools/fixtures/` (rhai or batch files) so they can be
  regenerated when the format changes; the generator script is committed next to the output.
- Realistic suites: `house-small` (2k faces), `cabinet` (components, arrays), `site` (large
  coordinates, 500 m), `curves` (arcs, circles, sweeps), `imports/*` (one per format incl. known
  bad files), `stress-1M` (generated, not committed; built in CI nightly).

## 4. CI matrix

| Job | Platforms | Steps |
|---|---|---|
| lint | ubuntu | `cargo fmt --check`, `cargo clippy --all-targets --all-features -D warnings`, `cargo deny check`, `cargo doc -D warnings`, architecture-boundary check (script greps `Cargo.toml`s) |
| test | ubuntu, macos, windows | `cargo test --workspace --all-features` |
| wasm | ubuntu | `cargo check --target wasm32-unknown-unknown -p planyrith-gui`, `wasm-bindgen-test` headless Chrome, size budget check |
| render | ubuntu (lavapipe), macos, windows | snapshot tests; upload diffs as artifacts |
| fuzz (nightly) | ubuntu | 10 min per target, corpus committed |
| bench (nightly) | ubuntu | criterion, regression > 10 % fails with report |
| release | all | build binaries, `trunk build --release`, checksums, attach to GitHub release |

## 5. Coverage and gates

- Core line coverage ≥ 85 % (`cargo-llvm-cov`), kernel modules ≥ 95 %.
- No `unwrap/expect` in core (clippy lint), no `unsafe` (lint), no `todo!()` on main.
- Every public command has at least one CLI golden test.
- PR template requires the checklist from `docs/05 §13` for tools.

## 6. Performance tests

- Benchmarks with fixed inputs; thresholds from `docs/00 §6` and `docs/06 §12` encoded as
  criterion baselines; frame-time budget test renders `stress-1M` headless and asserts ≤ 8 ms
  GPU time on the CI GPU class (recorded, not blocking on software adapters).

## 7. Manual QA scripts

`docs/qa/` (added at 0.3) holds scenario scripts (e.g. "model a room in 10 steps") executed by
humans or GUI automation before releases, with expected screenshots.

## 8. Issue triage labels

`kind:bug|feature|spec`, `area:kernel|tools|render|ui|cli|io|web|ext`, `severity:S1..S4`,
`good-first-issue`, `needs-spec`.

## Decisions

- 2026-10-20 — Undo/redo byte-equality is a required test for every command.
- 2026-10-20 — Render snapshots are blocking on real-GPU runners, advisory on software adapters.
- 2026-10-20 — The first CI workflow implements the lint, test and wasm jobs. The wasm job checks
  `planyrith-core` only until `planyrith-render` and `planyrith-gui` contain wasm-ready code;
  `cargo doc` and `cargo deny` run in the lint job; render, fuzz, bench and release jobs are
  added with their milestones.
- 2026-10-20 — **Undo/redo byte equality and the pid counter.** `next_pid` only moves forward
  (docs/04 §2), so after apply → undo the counter differs from the original file. The §2 check
  writes both documents with the same counter; everything else must be byte-identical. Implemented
  for every 0.1 command in `commands::undo_tests` (drawing, editing and organizing sequences, each
  step undone and redone in place).
