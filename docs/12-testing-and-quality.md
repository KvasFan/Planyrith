# 12 — Testing and quality

**Audience:** implementing agents. Normative.

## 1. Test pyramid

| Layer | Tooling | What |
|---|---|---|
| Unit | `cargo test`, `proptest` | kernel operations, units parsing, query parser, tolerance helpers, migrations |
| Golden | fixtures under `crates/planyrith-core/tests/fixtures/` | native format per version, importer outputs, inference results (JSON), CLI outputs |
| CLI integration | `assert_cmd`, `predicates` | every command via `planyrith tool`, batches, exit codes, JSON schema conformance |
| RPC integration | in-process server + client | every RPC method; GUI-attach scenario |
| Render snapshots | headless `wgpu` (software adapter in CI) | per style/feature, per-pixel tolerance (`docs/06 §11`) |
| GUI | `egui` test harness (kittest) + scripted input | tool state machines, panels, shortcuts; smoke on each platform |
| Web | `wasm-bindgen-test` in headless Chrome | storage, open/save, basic modeling |
| Fuzz | `cargo-fuzz` | native reader, every importer, mesh op sequences, query parser, units parser |
| Bench | `criterion` | add_edge, face finding, push-pull, boolean, extraction, inference, open/save |

## 2. Invariant checks

- `HalfEdgeMesh::validate()` runs after every kernel operation in debug builds and in all tests;
  release builds run it in `planyrith validate` and after import.
- Undo/redo determinism: for every command test, apply → undo → compare to original bytes
  (`.plyr` deterministic save) → redo → compare to post-apply bytes.
- Cross-frontend equivalence: GUI tool tests feed the same `Params` the state machine produced
  into the CLI and assert identical documents.

## 3. Fixtures policy

- Small (< 1 MB), generated by scripts in `tools/fixtures/` (rhai or batch files) so they can be
  regenerated when the format changes; the generator script is committed next to the output.
- Realistic suites: `house-small` (2k faces), `cabinet` (components, arrays), `site` (large
  coordinates, 500 m), `curves` (arcs, circles, sweeps), `imports/*` (one per format incl. known
  bad files), `stress-1M` (generated, not committed; built in CI nightly).

## 4. CI matrix

| Job | Platforms | Steps |
|---|---|---|
| lint | ubuntu | `cargo fmt --check`, `cargo clippy --all-targets --all-features -D warnings`, `cargo deny check`, `cargo doc -D warnings`, architecture-boundary check (script greps `Cargo.toml`s) |
| test | ubuntu, macos, windows | `cargo test --workspace --all-features` |
| wasm | ubuntu | `cargo check --target wasm32-unknown-unknown -p planyrith-gui`, `wasm-bindgen-test` headless Chrome, size budget check |
| render | ubuntu (lavapipe), macos, windows | snapshot tests; upload diffs as artifacts |
| fuzz (nightly) | ubuntu | 10 min per target, corpus committed |
| bench (nightly) | ubuntu | criterion, regression > 10 % fails with report |
| release | all | build binaries, `trunk build --release`, checksums, attach to GitHub release |

## 5. Coverage and gates

- Core line coverage ≥ 85 % (`cargo-llvm-cov`), kernel modules ≥ 95 %.
- No `unwrap/expect` in core (clippy lint), no `unsafe` (lint), no `todo!()` on main.
- Every public command has at least one CLI golden test.
- PR template requires the checklist from `docs/05 §13` for tools.

## 6. Performance tests

- Benchmarks with fixed inputs; thresholds from `docs/00 §6` and `docs/06 §12` encoded as
  criterion baselines; frame-time budget test renders `stress-1M` headless and asserts ≤ 8 ms
  GPU time on the CI GPU class (recorded, not blocking on software adapters).

## 7. Manual QA scripts

`docs/qa/` (added at 0.3) holds scenario scripts (e.g. "model a room in 10 steps") executed by
humans or GUI automation before releases, with expected screenshots.

## 8. Issue triage labels

`kind:bug|feature|spec`, `area:kernel|tools|render|ui|cli|io|web|ext`, `severity:S1..S4`,
`good-first-issue`, `needs-spec`.

## Decisions

- 2026-10-31 — **Installable preview.** Release distribution and publication
  gates are specified in docs/16. Windows tests install, run the historical
  format module, save/reopen native data and uninstall; Linux tests extracted
  Debian/Arch/portable payloads and FUSE-free AppImage execution. Main CI enables
  the rendering CLI feature used by every distributed binary.
- 2026-10-31 — **Historical/backup preview (alpha.2).** All 554 workspace tests
  pass with GPU/converter required (one existing ignored benchmark), including
  2013–2016 file geometry, original-version restoration, edited 2017 output,
  SKB import/export and byte-exact undo/redo; CLI/RPC/GUI native defaults,
  collision protection, explicit foreign choice persistence and the actual
  first-save dialog. The private large-model desktop round trip remains green.
  Three headless Chromium tests, native/wasm clippy, fmt, rustdoc, cargo-deny and
  optimized desktop/web builds pass. The web payload is 5,495,108 brotli bytes.
- 2026-10-31 — **Complex classic-model opening.** The 0.11.0-alpha.1 build
  passes 548 workspace tests with the converter and GPU required (one existing
  ignored benchmark), native/wasm clippy, fmt, rustdoc and cargo-deny. Eight new
  helper regressions cover classic colors/trailing definitions, class tags,
  bitmap pixels/alpha, warped polygons and holes, fragmented curves, coincident
  vertices and crossed wires. A private 99,216,575-byte 2019 model opens in
  about 23 seconds in the optimized build: 193,201 native faces, 130 image
  assets, zero validation problems. The opt-in desktop session test also
  passes native save/reopen canonical equality and byte-exact restoration of
  its original SKP. No private model or extracted content is committed. One
  below-tolerance facet is retained as boundary wires; source bytes remain
  intact. Desktop CLI/GUI/converter release builds succeed.
- 2026-10-30 — **0.11.0-alpha.1 preview.** 538 workspace tests pass with GPU
  and converter required (one existing ignored benchmark), plus three headless
  Chrome tests. `label-style` has a CLI batch/canonical golden, byte-exact undo,
  invalid/locked-context atomicity, fuzz coverage, RPC and CLI/GUI parity checks.
  GPU tests distinguish independently colored dimension groups before CPU text
  rendering. Both SKP writers retain edited annotations/live anchors/font/color,
  analytic curves, repeated image round-trips without orphan definitions,
  styles/watermarks/geographic sun and scene appearance. GUI SKP -> edit ->
  native working copy -> SKP tests cover the same behavior. Native/wasm clippy,
  fmt, rustdoc, cargo-deny and the separate-converter dependency boundary pass.
  Optimized desktop binaries and web bundle build; brotli total is 5,493,075
  bytes, below the 12 MiB budget. Release CLI smoke tests open 2019/2020/2026
  files and export/reopen edited annotation fixtures in 2017/2026. Remaining
  compatibility limits keep full 0.11 acceptance in progress.

- 2026-10-30 — **Editable SKP import and classic archives.** 527 workspace
  tests pass (one pre-existing ignored test) with the converter and GPU required.
  Positive SDK-saved 2019/2020 regressions recover the missing 254 mm square;
  pinned arcs/nesting/texture/text/watermark fixtures extend the corpus.
  Generated 2017/2026 imports test native annotation/font/layout retention,
  associative edge and radial measurements, nested merge/reuse/undo, image
  placement/assets, styles/fog/watermarks, geographic shadows and scene settings.
  Malformed annotation coordinates and truncated classic archives fail safely.
  Native/wasm clippy, rustdoc, fmt, cargo-deny, fixture download hashes and
  architecture boundaries pass. CLI, GUI and converter release builds succeed;
  release CLI smoke tests cover 2019/2020/2026. A locally inspected 2.2 MB house
  retains 318 faces, 51 definitions and 11 image assets (including previews),
  validates without errors and restores its source byte-for-byte after native
  save/reopen. External source content is not committed. These checks do not
  certify every release or complete edited-export/visual fidelity.

- 2026-10-30 — **Native-first SKP fidelity increment.** 515 workspace tests
  pass with the converter and GPU required. Real-process CLI/GUI tests retain
  the exact source through native saves/reopens. Regressions cover foreign
  archive streams, history/timestamp changes, camera and Sheets edits, consumed
  PID allocation after undo, explicit writer versions, and failed decoders
  returning no geometry. A locally inspected 2.2 MB house also survives a

- 2026-10-30 — **SKP and drawing completion (0.10).** Native workspace tests
  pass with the optional converter and GPU required, including real-process
  import/export/open/save, byte-exact import undo, original blank-template
  2017/2026 cube fixtures, repeated/nested components, two-sided textures/UVs,
  holes, wire edges, sections, attributes and scale properties. Regressions cover
  conflicting face sides and copied hidden edges, reordered source vertices,

  brotli (budget: 12 MiB). CI also checks that the optional GPL codec cannot

- 2026-10-30 — **Sheets acceptance (0.9).** The reproducible house fixture in
  `tests/fixtures/sheets` has plan, section and elevation layout goldens and a
  three-page A4 PDF. An independent parser measures PDF stroke operands for a
  1 m cube at 1:20: 50 mm within 0.01 mm. Tests cover live dimension updates,
  custom cameras retaining scene appearance, nested section overrides, frozen
  dimensions/image lifetimes, native round-trips and byte-exact undo. All 23
  commands have CLI goldens; CLI/RPC/Rhai, synthetic GUI input and browser
  persistence/export are exercised. Local checks pass: 485 workspace tests,
  14 focused Sheets tests, three headless Chrome tests, five GPU-required
  snapshots, native/wasm clippy, rustdoc and cargo-deny. `pdfinfo` reads the three
  A4 pages and `pdftotext` extracts Unicode; external DXF audits report zero
  errors and fixes for vector and raster exports. Reproduce the drawing outputs
  with `cargo run -p planyrith-core --example generate-sheets`. The release web
  build totals 5,450,507 bytes with brotli, below the 12 MiB budget.
- 2026-10-20 — Undo/redo byte-equality is a required test for every command.
- 2026-10-20 — Render snapshots are blocking on real-GPU runners, advisory on software adapters.
- 2026-10-20 — The first CI workflow implements the lint, test and wasm jobs. The wasm job checks
  `planyrith-core` only until `planyrith-render` and `planyrith-gui` contain wasm-ready code;
  `cargo doc` and `cargo deny` run in the lint job; render, fuzz, bench and release jobs are
  added with their milestones.
- 2026-10-20 — **Undo/redo byte equality and the pid counter.** `next_pid` only moves forward
  (docs/04 §2), so after apply → undo the counter differs from the original file. The §2 check
  writes both documents with the same counter; everything else must be byte-identical. Implemented
  for every 0.1 command in `commands::undo_tests` (drawing, editing and organizing sequences, each
  step undone and redone in place).
- 2026-10-25 — **Engine fuzz** (`commands::fuzz_tests`, §1–§2): random sequences of drawing,
  push/pull, offset, move/rotate/scale (with copies), erase modes, delete, grouping, explode,
  hide, tags and materials on a 100 mm lattice, targets picked by pid. After every successful
  command the document validates clean; a failed command leaves the bytes unchanged; replaying
  gives the same bytes; saving and reopening after every command gives the same document up to
  reserved keys; undoing everything gives the empty document and redoing everything the final
  one. `PLANYRITH_FUZZ_CASES` sets the number of sequences (24 by default).
- 2026-10-25 — **Render snapshots** (`planyrith-render/tests/snapshots.rs`): a small furnished room
  in every face style, two projections and a selection with an edit context, 320×200 with 4×
  MSAA, compared with golden PNGs at 2/255 per channel and ≤ 0.1 % differing pixels
  (`PLANYRITH_UPDATE_GOLDEN=1` rewrites them), plus id-buffer picking. The tests skip without a
  graphics adapter unless `PLANYRITH_REQUIRE_GPU=1`, which CI sets on all three OSes (lavapipe
  is installed on Linux; Windows uses WARP, macOS Metal); failing runs upload the actual images.
- 2026-10-25 — Each QA script in `docs/qa/` has an automated twin that drives the GUI shell with
  synthetic input in `cargo test` (headless, no GPU); the expected screenshot is rendered
  headless from the document the twin builds. The first is `model-a-room.md` (0.3).
- 2026-10-25 — `PLANYRITH_SCREENSHOTS=<dir> cargo test -p planyrith-gui screenshots` writes
  whole-window PNGs of the GUI (both themes, a tool hovering the model, the context menu)
  through `egui_kittest`'s wgpu renderer, optionally with `PLANYRITH_SCREENSHOT_DOC=<file>`
  loaded. It is a review aid, not a golden test: without the variable it does nothing.
- 2026-10-26 — **External validators (docs/13 0.5).** `tools/validate-exports.sh` builds the
  textured kitchen of the 0.4 acceptance batches, exports every format and runs other tools'
  validators: the Khronos glTF-Validator on GLB and glTF, ezdxf's recover/audit on 3D and 2D
  DXF, `xmllint` on SVG and `pdfinfo` on PDF. It downloads the glTF validator and ezdxf on first
  use, so it is a local check, not a CI job. Run on 2026-10-26: glTF-Validator 0 errors and
  0 warnings (GLB and glTF with textures), ezdxf 0 errors and 0 fixes (both DXF), SVG well-formed,
  PDF read by `pdfinfo`. In CI, every format has round-trip tests in the core
  (`commands::file::tests`), robustness tests on random and damaged files, and the
  `import_benchmark` (ignored) measures the 100 MB glTF case.
- 2026-10-26 — The snapshot with sun shadows (`room-section-shadows`) allows 1 % of its pixels to
  differ by more than 24/255: where a shadow-map edge falls depends on each adapter's depth

  The other snapshots keep the 2/255, 0.1 % tolerance of docs/06 §11.
